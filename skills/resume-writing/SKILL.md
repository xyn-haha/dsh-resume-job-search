# 简历写作与排版规范

本技能覆盖两件事：**写什么**（语气、结构、禁止表达、量化成果、删减策略）与**怎么排**（LaTeX moderncv 路线 + 中文优先的 Markdown 路线），二者的硬约束一致。

同目录参考文档（需要时直接读取）：
- `03-writing-style.md` — 写作风格总则（简历与求职信共用）
- `05-cv-templates.md` — 简历模板与定制细则
- 如有 `candidate-profile` 之类的候选人档案文档，撰写前必须先读取，所有主张以其为准。

---

## 一、绝对禁止的表达（逐条保留，违反即重写）

1. **禁止使用破折号（em dash，`--` 或 `——`）。** 改用逗号、句号，或重组句子结构。
2. **禁止套话与填充语。** 必须删掉：「我对……充满热情」「我相信我非常适合」「发挥我的技能」「立刻上手/马上能干活」「驱动结果」「协同效应」及其任何直译变体。
3. **禁止无实质支撑的空泛夸张词。** 每一条主张都必须有具体例子或事实支撑。
   - 反例：「具备出色的团队协作能力和极强的学习能力。」
   - 正例：「作为 5 人团队的核心开发者，负责前端全量设计与实现，项目获 XX 竞赛区域二等奖。」
4. **禁止道歉式或过度谦卑的表述。** 不写「我想我或许可以贡献一点」，而写「我能带来 X，已有 Y 作为证明」。
5. **禁止未经独立核实的公司主张。** 简历/求职信中出现的公司具体说法（合作关系、产品名称、技术描述、业务扩张、市场地位）在写入前必须通过网络搜索独立核实，不得直接采信其他 agent 或第三方转述。无法核实时，改为中性泛化表述或删除。
6. **禁止虚构经历。** 不得声称候选人没有的经历，不得暗示其涉足过并未真正涉足的领域。

> 检查方式：写完后用「破折号 / 套话 / 无支撑夸张 / 谦卑句 / 未核实公司主张 / 虚构经历」六项逐一 grep 式自查，命中任意一项即修改。

## 二、语气规则

- **热情但直接。** 友好、平易，但自信而不自大。
- **口语化的专业感。** 既不是僵硬的企业腔，也不是随意闲聊；标准是「一个自信的人在面试中会怎样说话」。
- **第一人称、主动语态。** 写「我构建了……」而不是「该系统由候选人开发」。
- **展示，而非陈述。** 不写「我是团队型选手」，而是写出一次具体的协作过程及其结果。

## 三、精确用词优先

- 岗位描述里出现的**原词**，只要真实适用，就优先于同义词使用（关键词匹配往往是字面匹配）。
- 绝不添加个人档案不支持的技能关键词（禁止堆砌关键词）。

## 四、可扫读结构

招聘方快速扫读，结构必须服务于快速抓取：

- 使用能反映内容的**描述性小标题**，不要只写「介绍」「正文」。
- 标题中在自然的位置嵌入行业关键词。
- 语言精炼，删掉一切填充语。
- **简历正文最多 2 页（硬规则，见第六节）。**

## 五、前瞻性表述

- 简历与求职信都应体现**你能为雇主解决哪些任务**，而非只罗列做过什么。
- 描述你会带来的方法、工具与知识。
- 说明雇主录用后可以期待什么正向结果。
- 过去的例子只用 1–2 个简短案例来支撑前瞻性主张。

## 六、版式硬约束

### 6.1 长度

- **简历必须正好 2 页**（不多不少）。下面给内容预算表；宁可删内容，不要压缩版式。

| 区块 | 内容上限 |
|------|---------|
| 个人简介（Profile statement） | 3–4 行 |
| 技能（Skills） | 5 条，每条 1–2 行 |
| 最近的项目 | 4–5 个要点 |
| 较早的项目/竞赛 | 2–3 个要点 |
| 教育（Education） | 2–3 条 |
| 认证（Certifications） | 1–2 条，每条单行 |
| 竞赛与获奖（Competitions & Awards） | 3 条，每条单行 |
| 推荐人（References） | 单行：「可按需提供。」 |

**存疑就删，不要挤。** 调小 `\vspace` 或版面缩放去硬塞内容，会让简历显得拥挤难看。

### 6.2 区块顺序（按岗位类型）

**安全 / 渗透测试类：**
1. 个人简介 / 电梯陈述
2. 核心能力 / 技能
3. 项目（旗舰项目放最前）
4. 竞赛与获奖
5. 教育
6. 认证
7. 语言
8. 推荐人

**蓝队 / SOC / 分析类：**
1. 个人简介 / 电梯陈述
2. 核心能力 / 技能
3. 教育（入门级岗位学历是主要凭证，前置）
4. 项目
5. 竞赛与获奖
6. 认证
7. 推荐人

### 6.3 各区块写法

**个人简介 / 电梯陈述（最需要定制的区块，位于标题下方）**
- 写 5–7 行，作为电梯陈述：简洁、有说服力地说明你为何胜任**这个具体岗位**，重点放在雇主能获得什么。
- 为每类主要岗位各准备 2–3 个简介模板（示例结构：学生身份 + 实操经验领域 + 旗舰项目与所用技术栈 + 熟练工具 + 求职意向）。

**核心能力 / 技能**
- 按目标岗位重排并加权，使用**加粗类别标签**。
- 列 **5–7 项关键能力**，逐项用一句话说明它为该岗位带来什么价值。

**教育**
- 始终包含最高学历；入门级岗位补充相关课程；与目标岗位相关时写论文/课题方向。

**职业经历（入门级改为「项目」区块）**
- 尚无正式工作经历时，以**项目**作为主要经历区块。
- 旗舰项目放最前；竞赛参与可作为项目相邻经历；最重要的项目用 4–6 个要点。
- 重点写技术决策、使用的工具与结果。

**入门级/学生身份的写法**
- 以项目与竞赛打头，而非工作经历；教育显著前置（它是主要凭证）；用认证与竞赛成绩证明能力；用个人简介把「学生」桥接为「有产出能力的贡献者」。

**竞赛与获奖**：保持简短，每条一行。**认证**：如实标注状态（如「已完成全部课程，考试待考」），既诚实又体现主动性。**推荐人**：列 2–4 位，含姓名、职务、公司、联系方式；末尾写「更多推荐人可按需提供」；**不要附推荐信原件**，雇主通常会直接联系推荐人。

### 6.4 量化成果写法（要点句型）

- 每个要点以**动作动词**或**加粗类别标签**开头。
- 必须具体：数字、工具、结果三者至少覆盖两项。
- **变换句式**，不要让每个要点都以同一种方式开头。
- 写不出的量化数据就不要编，改为写明具体范围、规模或产出物。
- 正例：`\item \textbf{流量审计}：基于 Scapy 实现深度包检测与协议分析，覆盖 5 类 IoT 设备行为识别。`
- 反例：`\item 参与了很酷的安全项目，学到了很多。`

## 七、LaTeX moderncv 路线（英文/多语种常规路线）

**输出文件：** `cv/main_<company>.tex`
**用 lualatex 编译**（MiKTeX/TeX Live）。pdflatex 在现代 MiKTeX 上常因 `fontawesome5` 字体扩展报错，lualatex 能干净地处理同一份源码。
**母版参考：** `cv/main_example.tex`（包含全部能力、经历与成果的完整简历，构建定向简历时用作素材来源）。

```bash
cd cv && lualatex -interaction=nonstopmode main_<company>.tex
```

预期输出：`Output written on main_<company>.pdf (2 pages, ...)`。**页数不是 2 即为失败，必须在交付给用户之前修好。**

### 7.1 文档骨架与颜色覆写（lualatex + MiKTeX 必需）

```latex
\documentclass[11pt,a4paper,sans]{moderncv}
\moderncvstyle{banking}
\moderncvcolor{blue}

% 这三行覆写必需：默认 banking 在 lualatex+MiKTeX 下会把姓名与区块标题
% 渲染成黑色，与蓝色强调配色（链接、项目符号、联系图标）不一致。
\renewcommand*{\firstnamestyle}[1]{{\fontsize{34}{36}\bfseries\upshape\color{color1}#1}}
\renewcommand*{\lastnamestyle}[1]{{\fontsize{34}{36}\bfseries\upshape\color{color1}#1}}
\renewcommand*{\sectionstyle}[1]{{\sectionfont\color{color1}#1}}

\usepackage[utf8]{inputenc}
\usepackage{hyperref}
\hypersetup{colorlinks=true, linkcolor=blue, filecolor=magenta,
  urlcolor=blue, pdftitle={<姓名> - CV}, pdfpagemode=FullScreen}
\usepackage[scale=0.77]{geometry}
\usepackage{import}
\begin{document}
\makecvtitle
% 区块顺序见 6.2
\end{document}
```

去掉覆写会导致姓名与标题在多数现代发行版上明显渲染错误，因此**不要删除**。若希望名以常规字重显示，把 `firstnamestyle` 的 `\bfseries` 改为 `\mdseries`。

### 7.2 itemize 列表内的间距（重要）

**不要**在 `itemize` 的 `\item` 之间插入 `\vspace{...}`。源码看起来对称，但条目间的 `\vspace` 会产生段落断点并与列表自身的 `\itemsep` 不可预测地相互作用，导致某一处间隙明显偏大。

```latex
% 错误：会偶发某一条项目符号前出现过大空隙
\begin{itemize}
\item \textbf{Foo}: ...
\vspace{1pt}
\item \textbf{Bar}: ...
\end{itemize}

% 正确：交给 itemize 使用原生均匀间距
\begin{itemize}
\item \textbf{Foo}: ...
\item \textbf{Bar}: ...
\end{itemize}
```

以下两种用法是正确的，应保留：`\section{...}` 之后紧跟的 `\vspace{1pt}`（位于标题与列表之间）；职业经历/教育区块顶层 `\cventry` 之间的 `\vspace{3pt}`（给不同经历留呼吸空间，渲染一致）。

### 7.3 常见分页问题与修法

| 问题 | 修法 |
|------|------|
| 条目标题留在第 1 页底部、要点被孤立到第 2 页 | 在该 `\cventry` 前加 `\needspace{5\baselineskip}`，preamble 中加 `\usepackage{needspace}` |
| 仅一个尾部区块溢出到第 3 页（如 References 独占第 3 页） | 在靠后的区块前加 `\enlargethispage{2-3\baselineskip}` 把第 2 页拉长几行（LaTeX 处理「差一点溢出」的标准补救手段） |
| 3 页且第 3 页有实质内容 | **删内容**，不要压缩 geometry 或 `\vspace`（见 7.5 相关性加权删减） |
| 第 2 页内容过早结束（显得单薄） | 恢复此前删掉的最高相关度条目；结束在第 2 页中部的简历看起来不完整 |

### 7.4 编译并逐页目视校验（强制）

写完简历、交付用户之前，必须编译并目视检查 PDF，循环迭代到版式干净为止：

1. 运行 `lualatex -interaction=nonstopmode main_<company>.tex`。
2. 检查输出页数：必须正好 2 页。
3. 打开/读取生成的 PDF，**逐页**目视检查（第 1 页与第 2 页都要看）。
4. 检查**孤行条目**：任何 `\cventry` 的标题行都不允许单独留在页底、其要点落到下一页。

### 7.5 相关性加权删减（正确缩小简历的方式）

**按信号删，不要按区块删。** 静态优先级清单（「先删最老的教育，再缩短最早的岗位」）在有相关度的「低优先级」条目与不相关「高优先级」条目竞争时是错的：一条直接对应岗位描述的老岗位要点，比一条不相关的新岗位要点更值钱。

对每个候选行按三项打分：

1. **与本岗位的相关度** — 是否命中招聘广告中点名的工具、关键词或职责？
2. **唯一性** — 这个主张是否只在此处出现，还是在简历中重复？
3. **叙事承载量** — 求职信是否依赖它？删掉它会迫使你重写求职信某段，说明它是承重行。

**删总分最低的那一行，不管它在哪个区块。**

实际删减顺序（最容易 → 最后手段）：
1. **冗余** — 同一成果同时出现在核心能力和岗位要点中时，通常删核心能力那份（经历要点是更具体的证据）。
2. **简介中的虚句** — 只是重复出版物/技能区块已展示内容的那句话。
3. **低相关度的经历要点** — 不触及岗位关键词的要点，不论在哪个区块；这一步先跨区块删，再动结构性清单。
4. **低相关度的支撑内容** — 不服务目标岗位的老岗位要点、不涉及岗位技术栈的认证、可压缩成一行的语言条目。
5. **低相关度的出版物** — 只留最匹配岗位的 1–2 篇，其余先删，再考虑动经历要点。
6. **最后的结构性删减** — 最老的教育条目、把老岗位压到 2 个要点、把认证合并成一行。只有上述加权删减全部用尽才做这一步。

**必须避免的坑：**
- 不检查相关性就机械地从静态区块清单底部往下删。「先删最老的岗位」在该岗位恰好就是岗位要求的那项技能时是错的。
- 不要删掉求职信所依赖的那一个具体例子。相关性是相对于你写的求职信来衡量的，不只是相对于岗位描述：面试官会同时读两份文件。
- 临界情况不要删内容：接近 2 页（约 2.02 页）时，优先在靠后区块用 `\enlargethispage{2-3\baselineskip}`；只有真正溢出（第 3 页内容超过单个尾部区块）才动用内容删减。

## 八、中文优先路线（Markdown → Pandoc/HTML → PDF 或 Word）

英文岗位或已有 moderncv 资产时走上一条路线；中文简历、或需要交付 Word 版本时走本路线。**硬约束与 LaTeX 路线完全一致。**

1. **单一内容源**：用 `resume.md` 作为唯一内容源（纯 Markdown，标题层级 = 区块顺序，`- ` 列表 = 要点）。所有措辞规则（第一至六节）在此文件上生效。
2. **PDF**：
   ```bash
   pandoc resume.md -o resume.pdf --pdf-engine=xelatex -V CJKmainfont="Noto Sans CJK SC" -V geometry:margin=2cm -V fontsize=11pt
   ```
   或：`pandoc resume.md -o resume.html --standalone`，用浏览器打印为 PDF（页边距 2cm，关闭页眉页脚）。
   - 必须用 xelatex（或 lualatex）引擎：pdflatex 无法直接处理中文字形。
   - 必须显式指定可用中文字体（如「Noto Sans CJK SC」「Source Han Sans SC」「微软雅黑」）；缺字体会静默回退成方框或乱码，需目视确认。
3. **Word**：`pandoc resume.md -o resume.docx --reference-doc=reference.docx`，交付前在 Word/WPS 中打开确认分页与项目符号样式。
4. **等价硬约束**：
   - 导出后**必须逐页目视校验 PDF**（第 1 页与第 2 页都要看），页数必须正好 2 页。
   - 不允许靠缩小字号/页边距把内容塞进 2 页；溢出时按 7.5 相关性加权删减处理。
   - 不能让某个区块的标题行孤留在页底而其内容移到下一页（对应 `\needspace{5\baselineskip}` 的等价做法：在 Markdown 中把该标题与其首条内容用「保持与下段同页 / keep-with-next」控制，或在 Pandoc 模板 CSS 中设置 `h2, h3 { break-after: avoid; }`）。
   - 导出后若字体、缩进或项目符号与预期不符，先修模板/字体设置，不要靠手工微调单次输出。
5. **版本管理**：留好 `resume.md` 作为可复用母版，按岗位派生 `resume_<company>.md`，不要在多份导出文件上直接改内容。

## 九、ATS 可解析性校验

多数雇主会先用 ATS 过滤简历，而 ATS 读的是 PDF 内嵌的**文本层**，不是渲染后的页面。简历可能通过视觉检查却在提取时变成乱码。版式通过 7.4 的循环后，校验文本层：

```bash
pdftotext -layout resume.pdf resume.txt   # LaTeX 路线同理：pdftotext -layout main_<company>.pdf main_<company>.txt
```

`pdftotext` 来自 [poppler](https://poppler.freedesktop.org/)，不属于 TeX 发行版，是**可选依赖**。未安装时跳过这项机械检查并明确提示风险，改为依据 PDF 目视阅读判断关键词覆盖。

提取结果检查项：

- **联系方式必须是字面文本。** 模板的字体图标会提取成字形名（`MOBILE-ALT`、`Envelope`），这属于无害噪声，因为真实地址和号码就印在旁边。真正的故障模式是某条联系方式**只**由图标或超链接承载（例如 `LinkedIn` 链接文字，其 URL 不在文本层中）：对 ATS 完全不可见。**邮箱地址必须始终以正文字面形式出现。**
- **不得出现乱码。** `(cid:NNN)` 标记或 `�` 字符说明字体缺少 Unicode 映射，ATS 看到的是同样的乱码。这通常出现在自定义模板的非常规字体上，标准 moderncv + lualatex 组合不会出现。
- **阅读顺序。** 标准 banking 风格是单栏，提取顺序与视觉顺序一致。带侧栏或多栏的自定义模板可能把无关行交错在一起；若提取顺序错乱，必须明确告知用户这是在用 ATS 兼容性换外观。
- **关键词覆盖。** 用岗位描述中的必备/加分术语，按岗位语言逐项比对提取文本。真实适用时优先使用岗位的原始术语而非同义词，ATS 匹配常为字面匹配。**绝不添加个人档案不支持的技能关键词。**
