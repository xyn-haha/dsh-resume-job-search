# 职业行为画像（Behavioral Profile）

本技能描述**候选人怎么工作、在什么环境下效率最高、哪些岗位语言是强匹配、哪些是潜在摩擦**。它回答的不是「会什么」（那是技能面），而是「以什么方式做事」（那是行为面）。

## 使用方式与数据纪律

1. 画像是**基于事实的推断，不是自我标榜**：每一格都要能指向 `candidate-profile/SKILL.md` 中的一条可证明经历或用户明确的自述。没有依据的维度写 `待补充`。
2. 画像变化时先更新 `candidate-profile/SKILL.md` 再更新本文件；两个文件不得互相矛盾。
3. 本技能在写作（简历/求职信/面试口径）之前读取，用来决定**语气与取舍**，不直接生成对外文本。
4. **隐私纪律**：本文件只登记行为倾向判断。真实姓名、学号、身份证号、精确住址、私人手机号、个人主页/仓库链接一律不写入；示例与表格一律使用占位符，例如 `<姓名>`、`<学校>`、`<专业>`、`<项目名>`、`<公司>`、`<岗位>`、`<竞赛名>`、`<证书名>`、`<时间区间>`。

## 一、画像维度

### 1. 核心行为驱动力

用一张表刻画「什么驱动这个人做事」，每项给档位与依据。档位建议用：**高 / 中 / 发展中 / 待补充**。

| 驱动力 | 档位 | 含义 | 依据（可证明来源） |
|---|---|---|---|
| 技术执行 | 高 | 动手实现、把方案跑通会带来动力 | <项目名>，<时间区间> |
| 精确与彻底 | 高 | 做事细致、确认细节、按流程推进 | <项目名> 中的具体交付物 |
| 学习与能力建设 | 高 | 通过系统学习持续积累专业能力 | <证书名>、<竞赛名> |
| 独立设定方向 | 发展中 | 更适应有明确目标的任务，独立制定长期路线仍在形成 | <事例或"暂无依据"> |

> 填写要求：档位不是褒贬，`发展中` 是中性描述；根据实际自述调整，不要照抄示例档位。

### 2. 最强行为

用「**行为名 + 一句可验证的描述**」的方式登记，建议 3 条左右：

- **可靠的执行者**：能按计划把事情彻底做完、做对，是团队里负责「让它落地」的人。<支撑事例>
- **细节导向**：在需要精细度和规范性的工作上保持方法化处理。<支撑事例>
- **持续学习者**：通过长期、结构化的自学建立能力，而不是被动等待培训。<支撑事例>

### 3. 高效工作环境

列出「什么条件下表现最好」，用于判断岗位环境是否吻合：

- 目标明确、期望清晰（谁负责什么、做到什么程度算好）。
- 允许在专业领域做深，而不是被迫频繁切换广度。
- 角色分工清楚的团队，而不是职责含糊、频繁救火。
- 动手实践多于纯抽象讨论。

### 4. 成长空间（对外表述时必须正向框定）

- **早期职业阶段 / 经验积累中**：对外框定为「有最新的知识结构、学习意愿强、愿意在带教下快速承担工作」，而不是「经验不足」。
- **方向设定仍在形成**：对外框定为「希望通过岗位接触不同方向后收敛专长」，并强调会主动请教与复盘。

> 框定的底线是**不夸大**：可以调整表达重心，不能把「发展中」说成「精通」，也不能凭空宣称战略规划或团队领导经验。

### 5. 管理风格偏好

- **配合得好**：方向明确、入职带教结构化、有定期反馈、有技术上的指导者。
- **配合得差**：期望含糊、优先级频繁变动且不给背景信息、无人带教的「自生自灭」式环境。
- 用途：面试反问环节与 offer 比较时，用来判断团队是否真的提供这些条件（见 `interview-prep` 的反问清单）。

## 二、画像与岗位语言的映射

拿到 JD 后，把 JD 用词与画像逐条对照，分成三档，写进岗位匹配评估：

**强行为匹配**（出现即加分，应在简历与面试中主动呼应）：
- 细节、严谨、条理清晰、流程规范
- 动手、实践、落地、可交付
- 学习意愿强、成长心态、愿意带教/被带教
- 团队协作、配合度高

**潜在摩擦**（记录但**不作为淘汰条件**，用于面试提问和预期管理）：
- 高度自主、极少监督、自己定优先级
- 快速变化、模糊不清的环境
- 一人多岗、职责边界未定义

**明显冲突**（需要提前向用户提示，例如岗位要求长期独立主导战略级项目、需要频繁即兴决策而无流程支撑）：写成风险提示，不写成「不要投」。

匹配结论必须区分三类表述：**已确认匹配**（有可证明经历支撑）、**推断匹配**（画像与 JD 语言一致但无直接事例）、**未知**（信息不足，面试时用反问确认）。

## 三、把画像用于写作语气

- **简历**：开头段落突出「按计划把复杂事情落地」的气质；经历描述多用动作动词 + 可验证产出，少用「精通」「深刻理解」这类空泛自我评价；把体现细致与执行力的项目放在靠前位置。
- **求职信**：语气务实、聚焦产出与配合度，例如「在<项目名>中我负责<职责>，交付了<产出>」；把早期职业阶段框定为「知识结构新 + 学习速度快」，并给出具体证据。
- **面试口径**：优先用**动手交付类**项目作为主线 STAR 素材（详见 `interview-prep` 的 STAR 结构）；回答协作类问题时落点在「对齐接口、推进卡点、把事做完」。
- **不要过度宣称**：不声称战略领导、不声称独立设定组织方向、不声称带过团队——除非 `candidate-profile` 中有实际依据。画像是用来聚焦表达，不是用来放大自我。

## 四、把画像用于岗位匹配判断

输出匹配评估时按下面顺序，避免只看技能面：

1. **技能匹配**：JD 硬性要求 vs `candidate-profile` 的技能三档（熟练/使用过/了解）。
2. **行为匹配**：用第二节的三档映射判断文化契合与摩擦点。
3. **环境匹配**：用「高效工作环境」与「管理风格偏好」核对团队形态（是否有人带教、分工是否清晰、是否长期救火）。
4. **结论**：给出整体建议（建议投递 / 可投但需注意 X / 不建议优先），并明确指出**匹配依据**与**未验证的假设**。

## 五、维护纪律

1. **可追溯**：每条画像结论标注来源（`candidate-profile` 字段名或用户明确自述），无来源的条目保持 `待补充`。
2. **不美化**：成长空间照实记录，对外表述时可以正向框定，但不能篡改事实。
3. **不诊断**：本技能不做人格测评或心理诊断，只描述与求职相关的工作方式。
4. **更新留痕**：修改后在文件末尾追加一行日期与改动摘要。
