# 面试准备（Interview Prep）

把面试拆成**可准备的过程**：轮次 → 题型 → 答案骨架 → 反问 → 复盘。本技能只提供方法论、结构与骨架，**任何具体经历、数字、证书名称都必须来自 `candidate-profile` 技能（同目录 `candidate-profile/SKILL.md`）**，本文件中的 `<...>` 全部是占位符。

## 使用方式

1. 先读取 `candidate-profile/SKILL.md`，把占位符替换为用户真实且可证明的经历；未登记的技能、经历、奖项视为不存在，**不得为了答题而虚构**。
2. 再读取目标岗位 JD，从 JD 里提取 3–6 个能力关键词（例如「细节把控」「跨团队协作」「长期实习」），面试叙事围绕这些关键词组织。
3. 准备产物建议落成三份清单：**项目/经历 STAR 卡**、**可能被问的问题 + 答案骨架**、**反问清单（按轮次）**。
4. 用户要求练习时，按本文「模拟面试流程」逐题进行，不要一次性把答案全部抛出。

## 一、中国求职市场常见面试轮次

| 轮次 | 通常由谁面 | 考察重点 |
|---|---|---|
| 简历筛选 / 笔试 / 在线测评 | HR、系统 | 硬性条件、基础能力，通过后才进入面试 |
| HR 初筛（电话/视频） | HR 或招聘专员 | 到岗时间、实习时长、求职动机、稳定性、薪资区间 |
| 技术面（1–3 轮） | 未来的直接同事、组长 | 基础功底、逻辑表达、项目真实性、动手能力 |
| 交叉面 / 总监面 | 其他团队负责人、部门负责人 | 跨团队协作、学习速度、抗压性 |
| 主管面 / 终面业务 | 业务负责人 | 项目理解深度、解决问题的方式、成长潜力 |
| 终面 HR | HR / HRBP | 动机、稳定性、期望薪资、到岗与背调信息 |

准备纪律：
- 每一轮都可能有「自我介绍 + 反问」，两样都必须按轮次准备版本。
- 投递前整理一份**简历口径表**：项目描述、时间、角色、数字在不同轮次必须一致，面试与简历互相矛盾是高频淘汰原因。
- 实习/应届岗位常问「能否长期实习」「每周可到岗几天」「能否接受出差或轮岗」，这类问题要在 HR 初筛前就想好答案。

## 二、回答的底层结构

### STAR 结构

按 **S（情境）→ T（任务/你的职责）→ A（你做了什么）→ R（结果）** 组织叙事，最后追加一句**反思**（学到了什么 / 重来会怎么改）。这是回答一切行为问题与项目问题的默认结构。

纪律：
- 时长：HR 初筛 60–90 秒；技术面里的项目简述 30 秒内给背景，细节在被追问时展开；完整 STAR 叙事控制在 2–3 分钟。
- **先给结论再给细节**：面试官更希望在开头就听到你的角色和结果。
- **给数字和事实，不给形容词**：「负责前端开发」要落到具体的模块数、缺陷数、处理量、耗时下降比例；没有量化时，写清交付物（代码仓库、演示地址、提交编号、上线效果）。
- **明确职责边界**：区分「我独立完成」与「我参与协作」，不要吞并团队成果。
- **结尾主动补反思**，体现成长意识。

### 表达上的三个常见减分项

- 贬低前雇主、学校、队友或竞争对手。
- 把团队成果全部说成个人成果。
- 用「比较」「挺」「还行」和空泛形容词堆砌，没有事实。

## 三、常见问题与答案骨架

以下骨架里的尖括号内容必须换成 `candidate-profile/SKILL.md` 中的真实字段。

### 1. 自我介绍

- 结构：**身份**（<专业> / <学历> / <毕业时间>）→ **方向**（目标岗位方向）→ **一到两个可证明的亮点**（<项目名> / <竞赛名> / <证书名>）→ **求职动机**（为什么投这个岗位）。
- 时长 60–90 秒，不要复述简历。
- 按目标岗位调整亮点顺序：投技术执行岗突出项目交付，投研究方向突出竞赛与方法论。

**英文自我介绍要点**：先写中文要点，再压缩成短句；不堆长句、不用生僻词。骨架：`I'm <姓名>, a <专业> student at <学校> graduating in <年份>. I focus on <方向>. I built <项目名>, where I was responsible for <你的职责>. I'm looking for a <岗位类型> role where I can <价值主张>.` 语速放慢，宁可重复要点也不要用背稿腔。

### 2. 项目/经历深挖（技术面最核心）

按标准问题链准备，每项各写一段 3–5 句的要点：

1. 项目背景：要解决什么问题，为什么值得做。
2. 你的职责边界：哪部分是你独立完成的。
3. 技术选型：为什么用这套方案。
4. 最大困难：卡在哪里、怎么定位、怎么解决。
5. 效果验证：怎么证明它有效，有没有可验证产出。
6. 如果重做：会改什么。

**追问陷阱**：面试官会沿着「为什么」连问三层，只要说到简历上写过的技术栈，就要能讲到实现细节；讲不到的部分宁可说「这部分是队友负责的，我了解接口层面的约定」。

### 3. 行为问题（团队协作、冲突、压力、失败、学习能力）

- 「讲一次团队协作」：用 STAR，落点在**你如何对齐接口、如何推动卡点**，而不是「我们很团结」。
- 「讲一次冲突」：选技术分歧，说明你如何用数据或实验比较方案，最后接受了什么结论。
- 「讲一次失败或出错」：选影响明确但破坏可控的事，讲清你的责任、补救动作、之后固化成什么流程。
- 「讲一次快速学习新东西」：给时间线（几天内从零到可用），说明学习路径和验证方式。

### 4. 岗位匹配类

- 「JD 上某个加分项你怎么看」：诚实说明「用过到什么程度」，并给出**已经做过的准备**（学过的课程、写过的脚本、做过的实验）。
- 「你为什么适合这个岗位」：把 JD 的关键词与自己的可证明经历一一对应，不匹配的部分明确承认并说明补齐计划。
- 「你还投了哪些公司 / 现在手上有 offer 吗」：真实但简短，重心放回「为什么这家是我优先级最高的」。

### 5. 不会的东西怎么答

三步骨架：**我知道什么**（相邻的、真实掌握的知识）→ **我不确定什么**（明确边界，不含糊）→ **我会怎么补**（推测思路 + 预计验证方式）。禁止硬编一个技术细节。

### 6. 技术面口述题

- 一边说一边给结构：**边界确认 → 思路 → 关键步骤 → 取舍理由 → 异常与失败场景 → 验证方式**。
- 先复述问题确认理解（「我理解你要问的是……」），不确定就澄清，比答偏更快挽回。
- 白板/共享屏幕场景：先写整体流程再补细节，保持口述与图一致。

## 四、难题应对

每类难题的目标不是「背一段漂亮话」，而是**承认事实 + 给出可证明的替代证据 + 说清正在补什么**。

- **「你没有专业的工作经验。」**
  骨架：先承接事实（「是的，我目前是<在校生/应届生>」）→ 给出可证明的实践证据（<项目名> 的交付物、<竞赛名> 的结果、<证书名> 的完成情况）→ 说清求职期望（实习/入门岗，能在<多长时间>内独立承担什么工作）。不要辩解、不要对比别人。

- **「为什么选这个方向（行业/岗位）？」**
  骨架：触发点（一个具体经历，而不是「从小感兴趣」）→ 方向的价值判断（这个领域未来几年为什么重要）→ 你已经投入的动作 → 希望在这家公司把这方向做深。

- **「五年规划？」**
  骨架：短期（毕业/转正后 1–2 年）打好工程与业务基础，成为可独立承担模块的人 → 中期在<方向>形成专长 → 长期能带小项目或负责一个方向。强调会随公司和业务调整，不做空想式承诺。

- **「你最大的缺点？」**
  骨架：选一个**真实但非本岗核心职责**的弱项 → 说明你已经采取的具体改进行动 → 给出当前进展。禁止用「我太追求完美」这类伪缺点。

- **「为什么选我们公司？」**
  骨架：必须针对每家单独准备，引用具体的东西（业务线、团队方向、公开技术分享、产品细节）→ 说明你的哪段经历或技能能对应上 → 表达长期意愿。给通用答案等于减分。

- **「期望薪资？」**
  骨架：先按城市、行业、职级做市场区间调研 → 给**区间**而不是单点 → 说明构成（税前月薪/年薪、是否含年终）与可谈部分 → 表示更看重成长与岗位内容。第一轮不主动报数字，除对方明确要求。

- **「这题答不上来 / 给不出具体例子」**
  骨架：坦诚说明 + 用相邻经历替代 + 现场推导思路。不要用编造的故事填补。

## 五、向面试官提问（反问）

每轮都可能出现反问，**至少准备 3 个**，按轮次选择；问题要基于本场对话追问，不要照本宣科。

### 岗位本身

- 这个岗位典型的一周是什么样子的？
- 入职后前六个月，做到什么程度算成功？
- 团队现在最头疼的问题是什么？

### 团队与协作

- 团队多大、怎么分工？
- 一个需求从提出到上线的完整流程是怎样的？
- 新人上手一般会怎么带？

### 技术与成长

- 团队现在用的技术栈和工具链是什么？
- 有没有机会往更专的方向深入（例如<方向一>、<方向二>）？
- 团队怎么跟进新的工具和行业变化？
- 有没有培训、导师或考证支持？

### 文化与发展（用来提前排雷）

- 你怎么描述团队的工作氛围？
- 团队里做得好的同事有什么共同点？
- 开发类工作和维护类工作的比例大概是多少？
- 团队的管理风格是怎样的？

### 实习 / 应届相关

- 到岗时间和实习时长有硬性要求吗？转正机制是怎样的？

### 谨慎使用的问题

**不要主动问**：薪资涨幅空间、同事的学校背景、「你们加班多吗」这类负面预设问题。加班强度、出差频率、弹性办公可以用中性方式确认（「这个岗位的工作节奏和出差频率大致是怎样的？」）。

## 六、模拟面试流程

用户要求练习时，按以下顺序执行：

1. 确认模拟对象：目标岗位、公司、轮次（HR 初筛 / 技术面 / 主管面 / 终面 HR）、时长。
2. 先让用户提供该项目对应的素材（`candidate-profile` 中的项目与经历清单、简历口径表），没有素材就先补齐。
3. 从简单热身题开始（「先做个自我介绍」）。
4. 进入岗位相关的问题：技术面的项目深挖链、笔试要点；HR 轮次的动机、稳定性、到岗时间。
5. 插入 1–2 个基于 JD 能力关键词的行为问题。
6. 以一道难题或一个意外问题收尾（例如突然改问另一个项目，或质疑某个技术选型）。
7. **每题答完立即给简短反馈**：说清「哪一句有效、保留」「哪一句要压缩或删掉」「建议用哪段素材回答哪类问题」。
8. 最后给一份本轮表现小结：优点、需要在下一轮补的题目、以及反问环节的建议。

节奏：纯文字模拟时保持一次一问，不要替用户答题；全流程模拟时按真实轮次的时限进行，并在结束后复盘。

## 七、电话/视频面试

- 面试前：检查设备与网络、找好安静环境与背景；准备一份**纸质提纲**放在视线外（关键数字、项目顺序、反问清单）。
- 微笑说话会改变语调；语速比平时略慢，遇到书面材料里的技术名词先在心里默读一遍再说。
- 听不清就问：「不好意思，能麻烦您重复一下吗？」——这是专业表现，不是减分。
- 允许用 5 秒思考再回答，不要用「嗯……那个……」填空。
- 结束前可以主动补一句：「关于我的背景，您还有什么想了解的吗？」

## 八、面试后的跟进

### 复盘（当天做）

每轮结束记录：被问到的题目、答得不好的地方、面试官反复强调的关键词。下一轮前据此调整答案。

### 状态跟进

- **不要为了「刷存在感」反复联系**，投递后主动联系容易造成负面印象。
- 对方给了时间线就按时等待；没有时间线且已过 2 周以上，可以简短询问进度。
- 如果有**真正新增且相关**的信息（新证书、新项目产出），可以简短补充说明。

### 感谢消息

- 收到任何状态更新（面试邀约、结果通知、拒绝）都可以发一条 2–3 句的简短感谢消息，感谢对方的时间与流程。
- 不要长篇大论、不要重复自我介绍、不要追问未到时间的决策结果。

### 接受或拒绝 offer

接受某个 offer 后，尽快礼貌告知其他在谈的公司并致谢，不拖延、不失联。

## 硬性纪律

1. **不编造**：任何未在 `candidate-profile/SKILL.md` 登记的经历、技能、奖项不得出现在答案里；面试官追问三层仍站得住的表述才算准备好的表述。
2. **口径一致**：面试答案、简历、求职信三者的时间、数字、角色必须一致。
3. **隐私最小化**：本技能只产出问题骨架与话术结构，不把用户真实姓名、学号、证件号、精确住址、私人联系方式写入技能文件或示例；示例一律使用 `<姓名>` `<学校>` `<项目名>` 这类占位符。
4. **诚实优先**：答不上来时的正确动作是承认边界 + 给推导思路，而不是硬编细节。
