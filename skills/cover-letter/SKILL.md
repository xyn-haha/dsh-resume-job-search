# 求职信写作与排版规范

本技能覆盖两件事：**写什么**（语气、结构、禁止表达、篇幅）与**怎么排**（LaTeX cover.cls 路线 + 中文优先的 Markdown 路线），二者的硬约束一致。

同目录参考文档（需要时直接读取）：
- `03-writing-style.md` — 写作风格总则（简历与求职信共用）
- `06-cover-letter-templates.md` — 求职信模板与定制细则
- 如有 `candidate-profile` 之类的候选人档案文档，撰写前必须先读取，所有主张以其为准；简历成品也应读取，二者不得互相矛盾。

---

## 一、绝对禁止的表达（逐条保留，违反即重写）

1. **禁止使用破折号（em dash，`--` 或 `——`）。** 改用逗号、句号，或重组句子结构。
2. **禁止套话与填充语。** 必须删掉：「我对……充满热情」「我相信我非常适合」「发挥我的技能」「立刻上手/马上能干活」「驱动结果」「协同效应」及其任何直译变体。
3. **禁止无实质支撑的空泛夸张词。** 每一条主张都必须有具体例子或事实支撑。
   - 反例：「我热爱网络安全，一定能快速融入贵司团队。」
   - 正例：「我在 <项目名> 中独立负责 <具体模块>，用 <技术工具> 实现了 <可验证结果>。」（用 `candidate-profile/SKILL.md` 中的真实项目名与真实指标替换占位符，不得使用示例中的数字）
4. **禁止道歉式或过度谦卑的表述。** 不写「我想我或许可以贡献一点」，而写「我能带来 X，已有 Y 作为证明」。
5. **禁止未经独立核实的公司主张。** 求职信中每一处公司相关的说法（合作关系、产品名称、技术描述、业务扩张、市场地位）在写入前必须通过网络搜索独立核实，不得直接采信其他 agent 或第三方转述。无法核实时，改写为泛化表述或直接删除。
6. **禁止虚构经历。** 不得声称候选人没有的经历，不得暗示其涉足过并未真正涉足的领域。

> 检查方式：定稿前按「破折号 / 套话 / 无支撑夸张 / 谦卑句 / 未核实公司主张 / 虚构经历」六项逐句自查。

## 二、语气规则

- **热情但直接。** 友好、平易，但自信而不自大。
- **口语化的专业感。** 既不是僵硬的企业腔，也不是随意闲聊；标准是「一个自信的人在面试中会怎样说话」。
- **第一人称、主动语态。** 写「我构建了……」而不是「该系统由候选人开发」。
- **展示，而非陈述。** 不写「我是团队型选手」，而是写出一次具体的协作过程及其结果。
- **不乞求、不过度热情。** 收尾要简短、自信、前瞻。

## 三、重述而非夸大：框架调整的边界

对经历做一定程度的岗位导向重述是预期的，但必须通过**面试回溯测试**：候选人能否在面试中从容解释这条内容而不需要「往回找补」？如果他要说「呃，我其实想说的是……」，那就过头了。

- **可以：** 重排经历次序把最相关的放前面；对目标领域使用自然同义词；突出宽泛角色中的某一方面。
- **需要标记：** 把学术经历与产业经历合写成一条仿佛全是产业经历的表述；用招聘广告的具体术语描述实际只是「相邻」而非相同的工作。
- **绝对禁止：** 声称候选人没有的经历；暗示其从事过并未涉足的领域。

当某条落在「需要标记」区间时，草稿完成后向用户提出：「这一条因为 X 属于拉伸表述，保留、弱化还是删除？」若岗位匹配度评分低于 50，在进入正式撰写前先警告：需要大幅重述才能贴合。

## 四、可选：申请标题/邮件主题写法

标题应具体、有吸引力，不要泛泛。

- 差：「应聘销售工程师职位」
- 好：「[你的专长方向] 专精于 [岗位描述中的相关关键词]」
- 公式：**[职位/学历] + [招聘广告中的相关关键词]**

## 五、可扫读结构与受众预期

- 使用能反映内容的**描述性小标题**，不要只写「介绍」「正文」。
- 标题中在自然位置嵌入行业关键词。
- 语言精炼，删掉所有填充语。
- 全文**最多 1 页（硬规则，见九.2）**。

## 六、前瞻性表述（求职信不是简历的复述）

- 聚焦**你能为雇主解决哪些任务**，而不是只讲过去做过什么。
- 描述你带来的方法、工具与知识。
- 说明雇主录用后可以期待的正向结果。
- 过去的例子只用 1–2 个简短案例来支撑前瞻性主张。

## 七、求职信结构

### 7.1 称呼（Salutation）
- 已知招聘经理姓名：「尊敬的 [名 姓]：」
- 已知团队：「尊敬的 [公司] 招聘团队：」
- 通用：「尊敬的 [公司]：」（**避免「敬启者」「致相关人士」这类无指向称呼**）

### 7.2 开头段（Opening Paragraph）
- 一句话说明你写这封信的目的与应聘岗位。
- 紧接着 1–2 句话把自身背景与该岗位连接起来。
- 必须针对这家公司/这个岗位，不得使用通用模板开头。

### 7.3 动机 / 为什么是这家公司（Why This Company，位置靠前）
- 开头段之后的**第一个区块**就要解释为什么申请**这家具体的公司**。
- 使用招聘广告与公司官网中的语言与主题。
- 聚焦你将如何为他们的目标做贡献，而不是你能从这份工作中得到什么。
- 如果你与该公司的人有过交流，自然地引用这次对话。

### 7.4 主体段（保任务解决导向）
- 从与本岗位最相关的经历写起。
- 内容围绕**他们哪些任务你能解决、如何解决**来组织。
- 描述你的方法：会带来的方法、工具与知识。
- 需要时用项目符号列出具体技能/成果（3–5 条）；每条都要具体、以结果为导向。
- 至少包含一个体现主动性的例子。
- 包含 1–2 个简短的过往成功案例，但整体保持前瞻。

### 7.5 公司专属段
- 展示你研究过这家公司（提到具体项目、价值观或市场定位）。
- 解释为什么是**这家**公司，而不是「像你们这样的公司」。
- 把你的领域知识与他们的业务背景连接起来。

### 7.6 结尾段（Closing）
- 简短、自信、前瞻。
- 可用「期待您的回复」「希望能有机会与您进一步沟通」这类表述。
- 不乞求、不过度热情。

### 7.7 项目符号写法
- 以动作动词或加粗类别标签开头。
- 要具体：数字、工具、结果。
- 变换句式，不要每条都以同一种方式开头。

## 八、按岗位类型的语言侧重

- **技术 / 机器学习类**：先写编程语言、ML 框架、具体模型架构；提到数据集、数据规模、流程复杂度；纳入独立项目。
- **领域专精类**：先写领域专长与具体方法；把技术能力定位为增强领域分析的工具。
- **咨询 / 顾问类**：先写干系人沟通、项目协调、客户交互；强调能打通技术视角与商业视角。
- **领导 / 资深类**：先写项目管理、带教、课程开发；把高等学位作为独立交付项目的证据。

## 九、篇幅与版式硬约束

### 9.1 长度（严格 1 页）
- 目标：含签名区在内**正好 1 页**。
- 上限：**绝不超过 1 页**。
- **正文字数预算 250–300 词**（不计 LaTeX 标记）；这是安全上限，350 词必然溢出。
- **段落要数**：开头段 + 项目符号段 + 结尾段 = 3 个区块；只有在其余段落都短时才加第 4 个。
- 增加公司专属内容时，同步削减其他内容，不要净增篇幅。

### 9.2 行距与间距
- 信较长且需要压到 1 页时，加 `\usepackage{setspace}` 与 `\setstretch{1.0}`。
- 主要区块之间用 `\vspace{.5cm}` 提高可读性（仅在空间允许时）。

### 9.3 项目符号列表
- `\begin{itemize}...\end{itemize}` 必须放在 `\lettercontent{}` **之外**（见 10.2），并包在匹配的 Raleway-Medium `\fontspec` 中，使项目符号字体与正文一致。
- 3–5 条最理想；每条以加粗标签或动作动词开头；类别式条目用 `\textbf{标签：}`。

### 9.4 LaTeX 特殊字符
- 下划线：`\_`；与号：`\&`。

### 9.5 非中文/多语种求职信
- 模板结构不变，内容使用招聘广告所用的语言。
- 日期格式改用当地惯例。
- 结尾敬语改用当地惯例（如丹麦语用「Med venlig hilsen,」）。
- 求职信的语言应与招聘广告一致，且读起来要自然，不能像翻译腔；某些语言中可以更温暖、更个人化一些。

## 十、LaTeX cover.cls 路线（XeLaTeX）

求职信使用自定义文档类 `cover.cls`，字体为 Lato/Raleway。

- **输出文件：** `cover_letters/cover_<company>_<role>.tex`
- **用 XeLaTeX 编译**（`cover.cls` 需要 fontspec）
- **字体目录：** `cover_letters/OpenFonts/fonts/`

```bash
cd cover_letters && xelatex -interaction=nonstopmode cover_<company>_<role>.tex
```

预期输出：`Output written on cover_<company>_<role>.pdf (1 page, ...)`。**页数不是 1 即为失败，必须在交付用户之前修好。**

### 10.1 文档骨架与关键命令

```latex
\documentclass[]{cover}
\usepackage{fancyhdr}
\pagestyle{fancy}
\fancyhf{}
\rfoot{Page \thepage \hspace{0pt}}
\thispagestyle{empty}
\renewcommand{\headrulewidth}{0pt}
\begin{document}

\namesection{}{\Huge{[姓名]}}{  \href{mailto:[邮箱]}{[邮箱]} | [电话] |  \urlstyle{same}\href{[LinkedIn 链接]}{LinkedIn}
}

\currentdate{\today}
\lettercontent{尊敬的 [姓名/团队]：}

\lettercontent{[开头段：岗位 + 背景连接，2-3 句]}

\lettercontent{[主体段：最相关经历，随后接项目符号列表]}

{\raggedright\fontspec[Path = OpenFonts/fonts/raleway/]{Raleway-Medium}\fontsize{11pt}{13pt}\selectfont
\begin{itemize}
    \item [具体成果/技能 1]
    \item [具体成果/技能 2]
    \item [具体成果/技能 3]
\end{itemize}\par}
\vspace{6pt}

\lettercontent{[与公司的连接：为什么是这个岗位、为什么是这家公司]}

\lettercontent{[个人契合段：行为优势、团队贡献，2-3 句]}

\lettercontent{期待您的回复。}

\begin{flushright}
% \closing{} 内部不要写行尾 \\ - cover.cls 会自行追加 \\，
% 双重换行会触发 "! LaTeX Error: There's no line here to end."
\closing{此致}
\signature{[姓名]}
\end{flushright}
\end{document}
```

| 命令 | 用途 |
|------|------|
| `\namesection{}{姓名}{联系方式}` | 含姓名与联系方式的页眉 |
| `\currentdate{日期}` | 日期字段（用 `\today` 或显式日期） |
| `\lettercontent{文本}` | 正文段落（其后自带间距） |
| `\closing{文本}` | 结尾敬语 |
| `\signature{姓名}` | 签名下方的印刷姓名 |

### 10.2 已知模板坑：`\lettercontent{}` 内嵌 itemize

`\lettercontent{}` 宏会在其参数末尾追加 `\\`。当参数以 `\end{itemize}` 结尾时，环境关闭后没有可断的行，于是报 `! LaTeX Error: There's no line here to end.` 且不产出 PDF。

**错误（编译中断）：**
```latex
\lettercontent{我的经历对应如下：
\begin{itemize}
    \item ...
\end{itemize}}
```

**正确：先闭合 `\lettercontent{}`，再给列表套上匹配的 Raleway-Medium 字体以保持排版一致：**
```latex
\lettercontent{我的经历对应如下：}

{\raggedright\fontspec[Path = OpenFonts/fonts/raleway/]{Raleway-Medium}\fontsize{11pt}{13pt}\selectfont
\begin{itemize}
    \item ...
\end{itemize}\par}
\vspace{6pt}

\lettercontent{[下一段]}
```

**字体包裹是强制的**：如果只是把 `\begin{itemize}` 移出 `\lettercontent{}` 而不加 `\fontspec` 块，项目符号会退回默认正文字体（Lato），与全信其余部分视觉不一致。

### 10.3 编译并目视校验（强制）

写完求职信、交付用户之前，必须编译并目视检查 PDF，循环迭代到版式干净：

1. 运行 `xelatex -interaction=nonstopmode cover_<company>_<role>.tex`。
2. 确认编译成功且页数正好 1 页。
3. 打开/读取生成的 PDF 逐页目视检查：签名区贴合页底、无文字被截断、项目符号字体与正文一致。

## 十一、中文优先路线（Markdown → Pandoc/HTML → PDF 或 Word）

中文岗位、或需要交付 Word 版本时走本路线。**硬约束与 LaTeX 路线完全一致（1 页 / 250–300 词 / 字体一致 / 逐页目视校验）。**

1. **单一内容源**：用 `cover_<company>_<role>.md` 作为唯一内容源；所有措辞规则（第一至八节）在此文件上生效。
2. **PDF**：
   ```bash
   pandoc cover_<company>_<role>.md -o cover.pdf --pdf-engine=xelatex -V CJKmainfont="Noto Sans CJK SC" -V geometry:margin=2.5cm -V fontsize=11pt
   ```
   或：`pandoc ... -o cover.html --standalone` 后用浏览器打印为 PDF（A4、页边距 2.5cm、关闭页眉页脚）。
   - 必须用 xelatex（或 lualatex）引擎，pdflatex 无法直接处理中文字形。
   - 必须显式指定可用中文字体；缺字体会静默回退成方框或乱码。
3. **Word**：`pandoc cover_<company>_<role>.md -o cover.docx --reference-doc=reference.docx`，交付前在 Word/WPS 中打开确认分页与项目符号样式。
4. **等价硬约束**：
   - 导出后**必须逐页目视校验 PDF**：必须正好 1 页，含签名区；签名不得被挤到第 2 页。
   - **项目符号列表的字体与正文一致**（对应 LaTeX 路线的 fontspec 约束）：在 Pandoc 模板/CSS 中统一 `ul li` 与正文字体，不要靠手动加粗或改字号硬凑。
   - 不允许靠压行距/字号把内容塞进 1 页；超出时按 9.1 削减内容（同步削减其他段落，不净增篇幅）。
5. **命名与提交**：文件名清晰，如「[姓名] 求职信」。

## 十二、交付前检查清单

- [ ] 无破折号（用逗号或句号）
- [ ] 无套话、无空泛填充语
- [ ] 每条主张都有具体例子支撑
- [ ] 前瞻性表述：聚焦你能解决的任务，而不是仅罗列过去职责
- [ ] 动机段引用了这家具体公司的使命/价值观
- [ ] 公司名与岗位名全文正确一致
- [ ] 日期是最新的
- [ ] 篇幅正好 1 页（正文 250–300 词）
- [ ] 语言与招聘广告语言一致，无翻译腔
- [ ] 称呼恰当（能点名到人就不写通用称呼）
- [ ] 标题/主题具体、有吸引力，非泛泛而谈
- [ ] 如提及 AI 辅助工具，按真实使用情况点名（例如 DSH / DeepSeek Harness 或 Claude Code），不得虚构使用经历
- [ ] 未虚报任何经历；拉伸表述已按第三节标记并请用户裁决
- [ ] 所有公司相关说法已独立核实
- [ ] 与简历内容一致，无互相矛盾的表述
- [ ] 已逐页目视校验 PDF：正好 1 页、签名区贴合、无截断、项目符号字体与正文一致
- [ ] 文件命名清晰（如「[姓名] 求职信」），导出为 PDF 以保持格式
- [ ] 只提交雇主索取的材料，并遵守雇主的匿名化等具体要求
