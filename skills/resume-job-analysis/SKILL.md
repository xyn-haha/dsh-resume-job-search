# 简历编写与求职分析（主工作流）

本技能是插件的入口，负责把零散请求路由到具体能力，并守住三条红线：**事实不编造、匹配度先评估、产出必须校验**。

## 能力地图

| 需求 | 使用的技能 | 说明 |
|---|---|---|
| 维护个人事实底本 | `candidate-profile` | 所有写作的事实来源，先读它 |
| 岗位信息搜集与去重 | `job-search-intel` | 渠道检索、台账、批量排序 |
| 岗位匹配度评估 | `job-evaluation` | 评分表 + 结论 + 红旗 |
| 改写简历 | `resume-writing` | 版式、长度、量化写法、导出校验 |
| 撰写求职信 | `cover-letter` | 结构、语气、禁忌表达 |
| 面试准备 | `interview-prep` | STAR、项目深挖、反问 |
| 语气与岗位适配 | `behavioral-profile` | 画像 → 写作语气与岗位选择 |

## 触发路由

- 「帮我评估这个岗位 / 这个 JD 值不值得投」→ 只跑第 1–3 步。
- 「给 [公司] 写简历 / 改简历」→ 先跑第 1–3 步确认事实与匹配度，再跑第 4 步。
- 「写求职信」「面试准备」「找新岗位」「整理投递台账」→ 直接跳到对应步骤。
- 用户未提供 JD 时，**先索要原始 JD 文本或链接**，不要凭岗位名称脑补要求。

## 工作流

### 第 0 步：读取事实底本
读取 `candidate-profile` 技能，确认身份、教育、经历、项目、技能、证书、偏好是否完整。缺失字段先向用户提问补齐，**不猜**。

### 第 1 步：解析 JD
从链接或文本中提取：公司名、岗位名、部门、城市、工作制、语言要求、硬性要求（学历/年限/证书）、加分项、职责、薪资区间、投递截止时间、投递方式（官网/邮箱/平台）。

### 第 2 步：核实公司与岗位真实性
- 公司：官网、企查查/天眼查、招聘页是否一致。
- 岗位：是否为已过期、是否疑似外包/挂靠、薪资与职责是否明显不匹配。
- 记录核实结论与来源；无法核实的部分明确标注为「未核实」。

### 第 3 步：匹配度评估（门控）
使用 `job-evaluation` 的技能规则输出：技能匹配、经历匹配、行为/文化匹配、加分项覆盖、差距清单、风险红旗、总体结论（强 / 中 / 弱匹配）与建议动作。

**必须在此停下并询问用户是否继续投递。** 用户未确认前不得生成或修改简历。

### 第 4 步：针对性改写简历
调用 `resume-writing`：
1. 先读现有简历底稿（若存在），保留结构与风格。
2. 针对 JD 调整：个人陈述、技能排序、经历要点侧重、项目选取、关键词对齐。
3. **关键词只做真实对齐**：JD 用词与你的真实经历一致时改用 JD 原词；不支持的要求留空并在评估中说明，禁止堆砌。
4. 控制长度（中文简历 1–2 页；英文简历 2 页内），导出后**逐页目视校验** PDF，检查跨页断行、标题孤行、字号与页边距。

### 第 5 步：撰写求职信
调用 `cover-letter`：语言跟随 JD（中文岗位写中文，英文岗位写英文）、一段式或三段式结构、一页内、称呼准确、正文必须把「具体经历」对应到「岗位要求」，不使用夸张形容词。

### 第 6 步：面试准备
调用 `interview-prep`：按 JD 要求生成问题清单、STAR 答案骨架（引用你真实项目，不得虚构数据）、项目深挖预案、反问清单；并按 `behavioral-profile` 校准表达语气。

### 第 7 步：产出校验（不可跳过）
对照下方清单逐条打勾，任何一项不通过就回到对应步骤修改：

- [ ] 所有事实与 `candidate-profile` 一致，无虚构技能/经历/证书
- [ ] 公司名、岗位名、时间、联系方式准确
- [ ] 公司相关描述均已核实，未核实的已标注
- [ ] 简历长度合规，导出 PDF 已逐页目视检查
- [ ] 简历与求职信说法一致，无自相矛盾
- [ ] JD 关键词覆盖到位且未堆砌，真实差距保留可见
- [ ] 求职信称呼正确、一页内、语气与画像一致
- [ ] 台账（`job-search-intel` 的 tracker）已登记本次投递状态与下一步动作

### 第 8 步：更新台账
把岗位、公司、渠道、投递日期、使用的简历/求职信文件、状态、下一步动作写入求职台账，便于后续跟进与去重。

## 输出规范

- 面向用户汇报用简体中文；英文岗位的简历与求职信用英文原文。
- 阶段汇报固定结构：**结论 → 依据（可核实）→ 差距与风险 → 下一步动作**。
- 中间过程不要贴大段原文日志，只给结论与关键证据。
- 评估与写作分离：评估阶段不写简历，写作阶段不改评估结论（如需修正，明确说明修正原因）。

## 硬性纪律

1. **不编造**：任何写入简历/求职信的内容都必须能在 `candidate-profile` 中找到对应事实与证明材料线索。
2. **不越权**：不代替用户向任何招聘平台、邮箱或公司提交申请；只生成材料并给出投递步骤。
3. **不改他人数据**：不修改用户未授权的文件；台账与简历底稿的改动都要在汇报中说明。
4. **写操作最小化**：优先新增文件（`cv/resume_<公司>.md`、`cover_letters/cover_<公司>.md`），不覆盖历史版本。
5. **不确定就标注**：无法核实的薪资、岗位状态、公司信息，一律标注「未核实」并说明核实方式。
